## Approved Resolutions

### Q1: Multi-Component Signal Evaluation Model
**Resolution**: Hybrid A+ model — `construct` ValueExpr + `evaluateConstructSignal()` writes contiguously to f64 buffer. Matches existing implementation.
**Impact**: Topics 05, 24

### Q2: Color UnitType Sub-Field Naming
**Resolution**: Use `unit` (not `space`). Consistent with all other UnitType kinds: `{ kind: 'color', unit: 'hsl' }`
**Impact**: Topics 01, 23

### Q3: Scalar UnitType Kind Removal
**Resolution**: Match implementation — 6 concrete kinds: `none | count | angle | time | space | color`. Remove `scalar` and `norm01`.
**Impact**: Topic 01, GLOSSARY

### Q4: Obligation-Driven Normalization
**Resolution**: Adopt ODN. Fixpoint loop already implemented. Update canonical spec to reflect normalization engine that inserts blocks + solves types in a loop.
**Impact**: Topics 04, 27 (NEW)

### Q5: Pure Lowering Contract Specification Depth
**Resolution**: Specify LowerSandbox (T2), effects-as-data model (T2), purity enforcement (T2). Omit `loweringPurity` tagging.
**Impact**: Topic 25 (NEW)

### Q6: Stride Table Differences
**Resolution**: Match implementation. Add "stride 0 for shape2d/shape3d = non-sampleable" concept. cameraProjection stride=1 (FIXED from 16).
**Impact**: Topics 01, 24

### Q7: Lens System Implementation Model
**Resolution**: Lenses are port decorators (not edge decorators) compiled to blocks. No separate lens catalog — blocks can be used as lenses. Remove "transform subtype" language.
**Impact**: Topic 26 (NEW), GLOSSARY

### Q8: Color Block Cardinality Dependency
**Resolution**: Cardinality type variable system already implemented. Color blocks use it.
**Impact**: Topics 01, 23
