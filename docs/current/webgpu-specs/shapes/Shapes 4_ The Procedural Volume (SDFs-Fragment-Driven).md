This is the comprehensive technical specification for **Shape Taxonomy: Type 4: The Procedural Volume (SDFs / Fragment-Driven)**.  
For Oscilla v3.0, mastering Type 4 shapes is the key to decoupling visual fidelity from polygon count. Instead of pushing millions of vertices to approximate a smooth curve, we push a handful of vertices and evaluate perfect mathematical surfaces per-pixel. This architecture enables infinite zoom, boolean operations (CSG), and pristine 2.5D extruded volumes, but it requires a fundamental shift in how we manage the GPU pipeline.

**1\. Inputs and Outputs (The Data Contract)**

In a Type 4 pipeline, the Vertex Shader is demoted to a mere "Courier." Its only job is to deliver a blank canvas (a bounding box) to the Fragment Shader, where the actual geometry is instantiated via math.

### **1.1 Compile-Time Inputs (CPU)**

* **The Mathematical AST:** The Abstract Syntax Tree representing the Signed Distance Field (SDF) equation (e.g., $d \= \\sqrt{x^2 \+ y^2} \- r$).  
* **Proxy Geometry Definition:** The minimal bounding hull. For 2D shapes, a Quad (4 vertices). For 2.5D extruded shapes, a Cube (8 vertices).

### **1.2 Run-Time Inputs (GPU)**

* **ShapeBank (The Proxy):** Contains only the 4 or 8 local vertices of the bounding hull and their corresponding local UV coordinates (ranging from $-1.0$ to $1.0$).  
* **Arena\_Read (The State):** The specific parameters for the equation, isolated per instance:  
  * Arena\_PosX, Arena\_PosY \[f32\] (Center of the hull)  
  * Arena\_ScaleX, Arena\_ScaleY \[f32\] (Size of the hull)  
  * **Custom Equation Parameters:** e.g., Arena\_Radius, Arena\_CornerRounding, Arena\_Thickness \[f32\].

### **1.3 Outputs**

* **color (vec4\<f32\>):** The rasterized pixel, utilizing analytical anti-aliasing via $fwidth()$.  
* **frag\_depth (f32):** (Crucial for 2.5D) The modified depth value. Since the proxy geometry is a flat quad or simple cube, the fragment shader must write its own depth based on the SDF evaluation to ensure proper intersection with Type 1/2/3 meshes.

**2\. Data Layout and Storage Impacts**

Type 4 reverses the storage paradigm: it is incredibly cheap on the ShapeBank but demands wider allocation in the Arena.

### **2.1 The ShapeBank (Micro-Footprint)**

* **Storage Cost:** A rigid 2D quad proxy requires exactly 4 vertices and 6 indices. This consumes negligible VRAM.  
* **Reuse:** Every single 2D procedural shape in the entire application can point to the exact same ShapeID (Proxy Quad) in the Bank. The actual shape is defined by the WGSL fragment shader logic, not the indices.

### **2.2 The Arena (Parameter Sprawl)**

If a user creates a RoundedBox block, the compiler must allocate storage for its specific parameters.

* **Layout:** Offset\_Width \[10,000 floats\], Offset\_Height \[10,000 floats\], Offset\_Radius \[10,000 floats\].  
* **Impact:** The GpuLayout must meticulously map these custom parameters into the SoA structure. The Compute Shader updates them (e.g., modulating Radius with an LFO), and the Fragment Shader reads them via instance\_index.

**3\. The Fragment Math (Evaluating the Void)**

The core logic shifts entirely to the pixel level. The shader must answer two questions: "Am I inside the shape?" and "If I am on the edge, how transparent should I be?"

### **3.1 The Distance Evaluation**

The fragment receives an interpolated local coordinate (e.g., $p \= (-0.5, 0.5)$) from the Vertex Shader. It executes the exact SDF equation:

$$d \= \\text{length}(\\max(|p| \- \\text{bounds}, 0.0)) \+ \\min(\\max(|p|\_x \- \\text{bounds}\_x, |p|\_y \- \\text{bounds}\_y), 0.0) \- \\text{radius}$$

### **3.2 Anti-Aliasing (The Derivative Trick)**

If we just use if (d \> 0.0) discard;, the edges will be horribly jagged. We must soften the edge exactly 1 pixel wide, regardless of zoom level.

* We use hardware derivatives to determine how fast the distance field is changing relative to screen pixels:  
  $$\\delta \= \\text{fwidth}(d)$$  
* We calculate coverage (alpha) using a smoothstep across that 1-pixel boundary:  
  $$\\alpha \= 1.0 \- \\text{smoothstep}(-\\delta, \\delta, d)$$

### **3.3 The Early discard**

To save ALU cycles on complex lighting or coloring, we immediately abort execution if the pixel is entirely outside the anti-aliasing window:

Code snippet

if (d \> delta) { discard; }

## ---

**4\. Hard Invariants (The Unbreakable Rules)**

1. **The Bounding Hull Strictness:** The Proxy Geometry generated by the Vertex Shader **must** fully encapsulate the mathematical shape at all times. If the user sets Arena\_Radius \= 5.0 but the Quad is only scaled to 2.0, the shape will be brutally clipped. The compiler must inject automatic bounding-box scaling logic into the Vertex Shader based on the maximum possible SDF bounds.  
2. **Premultiplied Alpha Mandate:** Because SDFs rely on $\\alpha$ for anti-aliasing, the Fragment Shader must output vec4(color.rgb \* alpha, alpha). If standard alpha is used, overlapping SDFs will exhibit dark, dirty halos at their edges during blending.  
3. **Uniform Scale Only (The Distance Metric):** Standard SDF math relies on Euclidean distance. If the user applies a non-uniform scale (e.g., $X=2.0$, $Y=1.0$) via a standard matrix transform, the distance field becomes distorted, and the $\\text{fwidth}()$ anti-aliasing will fail (edges will look blurred on one axis and sharp on the other).  
   * *Rule:* Non-uniform scaling must be applied *inside* the SDF equation (modifying the parameters), not via the outer Transform Matrix.

## ---

**5\. Pitfalls to Look Out For**

* **Fill Rate Death (Overdraw):** If the bounding Quad takes up the entire screen, but the actual SDF circle is only 10 pixels wide, the GPU will execute the Fragment Shader for 2,073,600 pixels (on a 1080p screen), only to discard 99% of them. This will instantly kill performance.  
  * *Mitigation:* The Vertex Shader must tightly shrink the proxy quad to match the instance's specific Radius or Bounds parameter from the Arena.  
* **Depth Buffer Conflicts (2.5D):** If you are extruding an SDF into a 3D coin and writing to frag\_depth, you must write the depth *before* discarding transparent anti-aliased edge pixels, or you will create depth-tearing artifacts where the soft edge of a foreground object fails to occlude the background.  
* **Derivative Undefined at Origin:** For some SDFs (like a cone), the gradient $\\nabla f$ is undefined exactly at $d=0$ or at the origin. Normalization will yield NaN. Always add a microscopic epsilon: normalize(gradient \+ vec2(1e-5)).

**6\. Machine Verifiable Acceptance Criteria (AC)**

To guarantee the compiler and execution runtime correctly handle Procedural Volumes, an automated agent must verify the following:

### **Phase 1: Proxy Geometry & Bounds AC**

* **AC 1.1 (Dynamic Bounding Box Fit):**  
  * *Test:* Compile a graph with a SDF\_Circle block. Inject Arena\_Radius \= 150.0.  
  * *Assert:* The Vertex Shader output clip\_position for the 4 corners must strictly equate to a screen-space square of exactly $300 \\times 300$ pixels (accounting for the camera matrix). The bounds must not be hardcoded.  
* **AC 1.2 (Instance Parameter Allocation):**  
  * *Test:* Instantiate 1,000 SDF\_RoundedBox shapes.  
  * *Assert:* The GpuLayout must allocate discrete channels for Width, Height, and CornerRadius, and the generated Fragment WGSL must read these using arena\_read\[OFFSET \+ instance\_index\].

### **Phase 2: Math & Shader Execution AC**

* **AC 2.1 (Anti-Aliasing Precision):**  
  * *Test:* Execute a headless render pass of an SDF\_Circle with radius $10.0$ at the center of the screen. Sample the output pixel at exactly a distance of $10.0$ from the center (the exact mathematical edge).  
  * *Assert:* The output $\\alpha$ value must be exactly $0.5$ (within floating-point epsilon), proving the $fwidth$ boundary calculation is perfectly centered.  
* **AC 2.2 (Overdraw Guardrail):**  
  * *Test:* Render an SDF\_Circle with radius $0.0$.  
  * *Assert:* The GPU performance profiling counter (or a manual atomic counter injected into the fragment shader for testing) must register exactly $0$ fragment executions. The Vertex Shader must have collapsed the proxy quad.  
* **AC 2.3 (Premultiplied Color Output):**  
  * *Test:* Render a pure red (1.0, 0.0, 0.0) SDF with an edge pixel evaluating to $\\alpha \= 0.5$.  
  * *Assert:* The final color attachment output must strictly equal (0.5, 0.0, 0.0, 0.5).

By mastering Type 4 shapes, procedural rendering stays resolution-independent while respecting shared camera/depth and blend contracts.
