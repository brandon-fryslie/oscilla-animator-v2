This is the comprehensive technical specification for **The Developer Experience & Migration Strategy: The "WASM Boot"**.

This document defines the initialization sequence of the application. It details how we transition from a standard JavaScript bundle load to a hybrid JS/WASM environment, ensuring the Naga binary is fetched, compiled, and instantiated before the first pixel is drawn.

# The Developer Experience: The "WASM Boot"

**Objective:** Initialize the Rust-based compiler backend (Naga) with zero user friction.

**Invariant:** The application UI (Graph Editor) must **never** render until the WASM module is fully instantiated and bound.

**Mechanism:** A blocking "Splash Screen" state driven by a top-level BootService that orchestrates the WebAssembly.instantiateStreaming pipeline.

## 1. The Critical Path (Why we wait)

In a standard React app, you render the UI immediately. In Oscilla v3.0, this is dangerous.

- **The Hazard:** If the user drags a node onto the canvas before Naga is ready, the CompilerService will attempt to call compile_ir().

- **The Crash:** This function call is a binding to WASM memory. If the instance doesn't exist, the app crashes with a hard null pointer or undefined error.

- **The Solution:** We treat the WASM binary like a "Database Connection." The app cannot start until the connection is established.

## 2. The Boot Sequence (The Pipeline)

The boot process is a linear chain of asynchronous operations.

### 2.1 Stage 1: The Fetch (fetch)

We request the .wasm file from the CDN or local server.

- **Optimization:** Use \<link rel="preload" href="/wasm/naga_bg.wasm" as="fetch" type="application/wasm" crossorigin\> in index.html. This tells the browser to start downloading the binary *while* it is still parsing the main JavaScript bundle.

### 2.2 Stage 2: The Streaming Compile (instantiateStreaming)

We do **not** use await response.arrayBuffer(). That forces the browser to download the whole file before parsing.

- **Best Practice:** Use WebAssembly.instantiateStreaming(fetch(...), imports).

- **Benefit:** The browser compiles the WASM code to native machine code *as the bytes arrive* over the network. This reduces startup time by 30-50%.

### 2.3 Stage 3: The Binding (wasm-bindgen)

The raw WASM instance exports a flat memory buffer and function pointers. We need the JavaScript wrapper generated by wasm-bindgen to make sense of it.

- **Action:** Call the default export from the generated JS file: await initWasm().

- **Result:** The wasm object in global scope is populated with valid pointers.

## 3. The BootService Architecture

We encapsulate this logic in a singleton that acts as the "Gatekeeper."

TypeScript

// services/BootService.ts\
import initNaga from './wasm/oscilla_naga_shim';\
\
type BootState = 'initial' \| 'fetching' \| 'compiling' \| 'ready' \| 'error';\
\
class BootService {\
readonly state = new BehaviorSubject\<BootState\>('initial');\
readonly error = new BehaviorSubject\<string \| null\>(null);\
\
async start() {\
try {\
this.state.next('fetching');\
\
// 1. Trigger the load\
// The generated 'initNaga' function handles fetch + instantiateStreaming internally\
await initNaga('/wasm/oscilla_naga_shim_bg.wasm');\
\
// 2. verify\
// Run a tiny "Smoke Test" to prove it works\
this.runSmokeTest();\
\
this.state.next('ready');\
} catch (e) {\
console.error("WASM BOOT FAILED", e);\
this.error.next(e.message);\
this.state.next('error');\
}\
}\
\
private runSmokeTest() {\
// Attempt to compile an empty module. If this throws, the binary is corrupt.\
try {\
const result = compile_ir({ ...emptyModule });\
if (!result.is_valid) throw new Error("Smoke test validation failed");\
} catch (e) {\
throw new Error(\`WASM Integrity Check Failed: \${e}\`);\
}\
}\
}

The root React component subscribes to the BootService.

## 5. The Build Pipeline (Vite / Webpack)

Getting the .wasm file to the browser requires configuring the bundler.

### 5.1 The wasm-pack Workflow

1.  **Rust Build:** wasm-pack build --target web.

2.  **Output:** Generates pkg/oscilla_naga_shim.js and pkg/oscilla_naga_shim_bg.wasm.

3.  **Integration:**

    - Copy the .wasm file to the public/wasm/ folder of your web project.

    - Copy the .js file to src/wasm/ (or import directly if using a monorepo tool like Nx).

### 5.2 The MIME Type Trap

The most common error is TypeError: Failed to execute 'compile' on 'WebAssembly': Incorrect response MIME type.

- **Cause:** The dev server sends application/octet-stream.

- **Fix (Vite):** Vite handles this out of the box.

- **Fix (Express/Custom):** Ensure your static file server sends Content-Type: application/wasm for .wasm files.

## 6. Migration Strategy: The "Shim" Phase

You are migrating from a JS-only engine. You don't want to break everything on Day 1.

### 6.1 The Feature Flag

Wrap the WASM compiler usage in a feature flag.

- **Flag:** ENABLE_NAGA_BACKEND = true.

- **Logic:**

  - If true: CompilerService uses NagaService (WASM).

  - If false: CompilerService uses the legacy StringTemplate compiler.

### 6.2 The Hybrid Boot

During the transition, you might want the app to work even if WASM fails (fallback mode).

- **Strategy:**

  1.  Attempt WASM Boot.

  2.  If it fails, log a warning: "Physics Engine failed to load. Falling back to Legacy Mode."

  3.  Set ENABLE_NAGA_BACKEND = false.

  4.  Proceed to READY state.

- *Note:* This is only temporary. Once Phase 2 (Physics) lands, the legacy backend will be deleted, and WASM failure becomes fatal.

## 7. Versioning & Caching

The WASM binary is large (1MB). We must cache it aggressively.

### 7.1 Cache-Busting

We must ensure that when you update the Rust code, users get the new binary.

- **Hash Naming:** The build tool should rename the file to naga.\[hash\].wasm.

- **Implementation:** Pass the hashed URL to initNaga(url). Most bundlers (Vite) allow import wasmUrl from './naga.wasm?url' which gives you the hashed path automatically.

### 7.2 The Offline Cache

Service Workers can cache the WASM file.

- **Warning:** instantiateStreaming sometimes conflicts with Service Worker responses if the headers aren't perfect.

- **Workaround:** If the Service Worker intercept fails, fallback to arrayBuffer instantiation (slower but robust).

## 8. Summary of Implementation

1.  **Asset Setup:** Configure wasm-pack output to generate web target.

2.  **Boot Service:** Implement the class that calls init() and manages the loading state.

3.  **Root Component:** Wrap the application in a BootGate component.

4.  **Bundler Config:** Ensure .wasm files are served with the correct MIME type.

5.  **Smoke Test:** Write a simple compilation test that runs immediately after boot to verify the binary is functional.

This strategy treats the WASM module as a **System dependency**, effectively an "Operating System" for your instrument. The boot phase ensures that OS is booted before the user tries to launch any programs.
